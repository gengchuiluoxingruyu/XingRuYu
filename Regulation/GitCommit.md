# Git 提交规范

本文件是对 [[AGENTS]] 的补充说明：规定本库 commit message 的格式与粒度。遵守方式为自觉，不安装 commitizen、不配置 commit 模板。

>[!info] 定位
>- **给未来的自己看**：`git log` 要能一眼看出"哪次加了什么、哪次动了配置"，不必点开 diff。
>- **本库是笔记库不是代码库**：描述用中文，只有 `type` 前缀用英文。
>- **粒度比格式更重要**：一次提交只做一件事，比写得多漂亮都管用。

## 1. 格式

```
type(scope): 描述
```

- `type`：必填，只能取第 2 节表里的值，小写英文
- `scope`：选填，写明影响的区域，如 `copilot`、`regulation`、`daily`
- `描述`：必填，中文，动词开头，不加句号，不超过 25 个汉字（约 50 字符）

> [!example] 合格
> ```
> add: 添加 2026-11-16 日记
> config: 清理 types.json 中的废弃属性
> add(regulation): 新增标签使用规范
> move: 属性说明移入 Regulation
> ```

> [!warning] 不合格
> - `修改了文件` —— 没说改了什么，等于没写
> - `fix: 修复了一个小问题吧。` —— 描述含糊、带句号
> - `Add: 添加日记` —— `type` 必须小写
> - `添加日记` —— 缺 `type` 前缀
> - `update: 改了一些东西，顺便整理了下配置，还删了两篇旧笔记` —— 三件事挤进一次提交

## 2. type 取值

| type | 用于 | 例子 |
| --- | --- | --- |
| `add` | 新增笔记、剪藏、模板、素材 | `add: 添加 Git 提交规范` |
| `update` | 修改已有笔记的内容或属性 | `update: 补充属性说明中的示例` |
| `fix` | 修正错误：错别字、坏链接、错误属性值 | `fix: 修复 Properties 的失效链接` |
| `move` | 移动、重命名、调整目录结构 | `move: 剪藏统一移入 Row` |
| `remove` | 删除笔记或文件 | `remove: 删除重复的剪藏` |
| `config` | 配置变更：插件、主题、`.obsidian`、`AGENTS.md`、规范文档 | `config: 更新 copilot 技能配置` |
| `style` | 只调格式，不改内容 | `style: 统一各篇的标题层级` |
| `revert` | 撤销某次提交 | `revert: 撤销 c549bdb` |
| `chore` | 自动备份、工具产生的杂项提交 | `chore: vault backup` |

新增 `type` 前先想清楚是否真有必要，宁可归到现有的类里。

## 3. 粒度

- **一次提交一件事**：改内容和动配置分开；新增笔记和删除笔记分开（除非是同一次整理）
- 批量同类改动可以合并，但描述里要写清范围：`add: 添加 11 月前三周日记` 而不是 `add: 添加日记`
- 提交前先 `git status`，确认没有意外文件混进来
- 同一件事反复改了几次，最后整理成一次干净提交，别留下 `fix: 又改了一下`

## 4. 提交什么、不提交什么

**该提交**：笔记正文、`Template/` 模板、`Regulation/` 规范、`AGENTS.md`、`.obsidian` 中的类型配置（如 `types.json`）

**不提交**：`Cache/` 里的临时脚本与中间产物、`.trash/` 回收站内容、含密钥或个人隐私的配置、系统生成的临时文件

> [!warning] 密钥与隐私
> 提交前扫一眼 diff，确认没有 API key、token、个人路径之外的敏感信息。这类内容一旦进了历史，删掉文件也没用。

## 5. 与自动备份的关系

`vault backup` 这类由插件自动生成的提交属于 `chore`，不受第 1 节格式约束。但重要的结构性改动（改配置、移目录、删文件）建议手动提交一次，让历史里留下可读的一笔。

## 6. 提交前自检

- [ ] 有 `type` 前缀，且在第 2 节表内
- [ ] 描述是中文、动词开头、不加句号、25 字以内
- [ ] 这次提交只做了一件事
- [ ] `git status` 里没有意外文件
- [ ] 没有密钥、隐私或 `Cache/` 临时文件混入
