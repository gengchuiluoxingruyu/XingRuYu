# 属性使用规范

本文件是对 [[AGENTS]] 的补充说明：规定本库 frontmatter（属性）的命名、类型、取值与维护方式。手写笔记、模板与 AI 生成内容一律遵守。

>[!info] 定位
>- **属性即状态**：属性说明的是**这篇文件自身处于什么状态**——属于哪一类（`type`）、何时创建（`created`）、进行到哪、质量如何（`mood_*`、`focus_hours`）；它不说明文件讲了什么。
>- **属性**：由上一条落成的结构化元数据，给机器用的，用来检索、筛选、排序、聚合与批量处理。
>- **正文**：给人读的内容，观点、过程、细节都写在这里，不搬进属性。
>- **标签**：描述"这篇是什么、属于什么"的多维词，不承载日期、作者、状态等可控值。

## 总原则

| 原则 | 含义 |
| --- | --- |
| 只记状态 | 属性回答"这篇文件现在是什么情况"，不回答"这篇写了什么"；内容一律留在正文 |
| 最小必要 | 只登记影响检索与批量处理的字段，正文能表达的不建字段 |
| 值域受控 | 同义字段只留一个；枚举、日期、数值格式全库统一 |
| 可聚合 | 属性值要能分组统计，避免长篇自由文本 |
| 不为填而填 | 每个字段都能说出"谁用、用来做什么"；说不出就删掉 |
| 单一来源 | 本文件是约定的唯一出处，`.obsidian/types.json` 只是执行结果 |

## 命名规范

- 全部小写，多个单词用下划线连接：`mood_morning`、`focus_hours`、`date_added`
- 只用英文字母、数字、下划线；不用中文、空格、连字符、大驼峰
- 同一含义只允许一个字段名。`created` 与 `date_created`、`added` 不能并存
- 时间类字段统一前缀：`date_*`（日期）、`*_at`（时刻）
- 布尔字段用肯定式：`archived`，不用 `not_archived`
- 废弃字段不改名；先确认全库无笔记使用，再从 `types.json` 与字段表中一并删除（清理配置须单独确认）

## 类型与格式

| 类型 | 写法 | 约定 |
| --- | --- | --- |
| text | `title: 打造第二大脑` | 一句话、不含换行；含 `:` 或 `#` 时加引号 |
| number | `focus_hours: 2.5` | 纯数字，不带单位；小数位统一保留一位 |
| checkbox | `archived: true` | 只写 `true` / `false` |
| date | `date: 2026-11-16` | 严格 `YYYY-MM-DD`，不写 `2026/11/16`、`11-16` |
| datetime | `updated_at: 2026-11-16T21:30` | 需要时刻时用 `YYYY-MM-DDTHH:mm` |
| list | `aliases:` 换行 `  - 别名` | 每行一个值，不用逗号拼接 |
| tags | `tags:` 换行 `  - daily` | 只用于 `tags` 字段，值不带 `#` |
| link | `related: "[[某笔记]]"` | wikilink 必须加引号，否则会被解析成嵌套列表 |

- 空值不留空键：没值就整行删掉，不写 `author:` 空着
- 多值文本（如多个作者）用全角顿号 `、` 分隔，不用逗号
- 单位不写进数值字段，单位写在字段说明里（小时、百分比等）

## 笔记类型（`type`）

`type` 是唯一必填的受控枚举字段，决定笔记套用哪套模板与字段。

| 取值 | 用于 | 目录 | 模板 |
| --- | --- | --- | --- |
| `daily` | 每日日记 | `Log/DailyLogs/` | [[Daily]] |
| `clipping` | 网页、视频、文章剪藏 | `Row/` | 剪藏模板 |
| `note` | 自己整理的正式笔记 | `Wiki/` | — |
| `summary` | 每日做了什么的总结 | `Timestamp/` | [[Timestamp]] |
| `regulation` | 规范、约定类文档 | `Regulation/` | — |

- 新增取值必须先登记到本表，不允许临时自创
- 未定型的草稿仍在 `Row/`，标 `type: clipping`；整理进 `Wiki/` 时改为 `type: note`

## 字段表

### 通用

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `type` | text（枚举） | 是 | 见「笔记类型」节 |
| `created` | date | 是 | 笔记创建日；剪藏取导入日，不是原文发布日 |
| `updated` | date | 否 | 有实质修改时才写 |
| `tags` | tags | 是 | 1–5 个，见「标签与属性的分工」节 |
| `aliases` | list | 否 | 检索用的别称，不加 `[[ ]]` |

### 日记（`daily`）

| 字段 | 类型 | 必填 | 取值 |
| --- | --- | --- | --- |
| `date` | date | 是 | 该篇记录的那一天 |
| `weather` | text | 否 | `sunny` `cloudy` `overcast` `rainy` `snowy` `windy` `foggy` |
| `mood_morning` / `mood_noon` / `mood_night` | number | 否 | 整数 1–5，1 最差 |
| `focus_hours` | number | 否 | 0–16，一位小数 |
| `efficiency` | number | 否 | 已预留未启用，不要使用 |

### 剪藏（`clipping`）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `title` | text | 是 | 与文件名一致 |
| `source` | text | 是 | 原始 URL，单个链接 |
| `author` | text | 否 | 原作者，多个用 `、` |
| `published` | date | 否 | 原文发布日，未知留空 |
| `description` | text | 否 | 一句话摘要，不复制大段原文 |

### 正式笔记（`note`）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `related` | list | 否 | 相关联的笔记，wikilink 加引号 |
| `source` | text | 否 | 整理所依据的主要来源 |

### 遗留字段

当前无遗留字段（原 `rating`、`series_index`、`calibre_id`、`date_from`、`date_to`、`week`、`year`、`day`、`unit`、`date_started`、`date_finished`、`date_added`、`priority`、`mood`、`TQ_*` 已于 2026-11-16 确认全库未使用，并从 `.obsidian/types.json` 移除）。

- 不要再写入上述字段；需要书籍类字段时先在此登记新方案
- 弃用字段按「命名规范」节处理：确认无笔记使用后，连同 `types.json` 一并清理

## 属性与正文的分界

| 内容 | 放哪里 |
| --- | --- |
| 日期、评分、小时数、状态 | 属性 |
| 结论、过程、引用、待办清单 | 正文 |
| 多维分类（主题/类型/场景） | 标签 |
| 唯一归属（项目、领域） | 文件夹 |
| 长摘要、多段落背景 | 正文，属性最多留一句话 |

>[!example] 对照
>✅ `focus_hours: 3.5` + 正文写"下午被会议打断两次"
>❌ `focus_note: 下午被会议打断两次，所以只做了 3.5 小时`

## 标签与属性的分工

- 日期、作者、版本、评分、状态、优先级一律用属性，不做标签
- 标签只描述主题与类型，1–5 个，能用现有词就不新建
- 属性值是受控枚举（如 `type`、`weather`）时，不得改用标签表达
- 标签自身的命名、词表与维护见 [[Tags]]；逐条用法见 [[TagGuide]]
- 属性的逐条用法见 [[PropertyGuide]]

## 变更流程

1. 先查「字段表」与本库现有笔记，确认没有同义字段
2. 在本文件字段表中登记：字段名、类型、适用 `type`、必填、值域
3. 同步 `.obsidian/types.json` 的属性类型（此项需我确认后由我自己操作）
4. 更新对应模板，使新笔记自动带上该字段
5. 只改新笔记；批量回填旧笔记须单独提出并确认
