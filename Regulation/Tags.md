# 标签使用规范

本文件是对 [[AGENTS]] 与 [[Properties]] 的补充说明：规定本库标签（`tags`）的命名、取值与维护方式。手写笔记、模板与 AI 生成内容一律遵守。逐条的用法解释见 [[TagGuide]]。

>[!info] 定位
>- **标签即分类**：标签是给事物分类的词，说明"这篇讲的是什么、属于哪个主题"，不说明文件处于什么状态。
>- **状态归属性**：类别、时间、进度、评分等可控值，一律用 [[Properties]] 登记过的属性，不做标签。
>- **词表受控**：标签是共享词表，全库只有一个出处，就是本文件「词表」一节。

## 总原则

| 原则 | 含义 |
| --- | --- |
| 只做分类 | 标签回答"这篇讲什么"，不回答"这篇处于什么状态" |
| 词表受控 | 只用「词表」登记过的词；新词先登记再用 |
| 复用优先 | 能用现有词表达就不新建，同义词只留一个 |
| 可聚合 | 一个标签要能框住一批笔记；只服务一篇的标签等于没分类 |
| 单一来源 | 本文件是标签约定的唯一出处，笔记里的标签只是它的实例 |

## 命名规范

- 命名与属性名同一套规则：全部小写，多个单词用下划线连接，如 `second_brain`
- 只用英文字母、数字、下划线；不用中文、空格、连字符、`#`、大驼峰
- 同一含义只允许一个标签：`clippings` 与 `clipping` 不能并存
- 不与 `type` 的取值重复表达同一件事；标签说的是主题，`type` 说的是类别
- 标签废弃时不改历史笔记，在「词表」里标记"停用"，新笔记不再写

## 词表（受控）

| 标签 | 分类维度 | 用在哪 | 状态 |
| --- | --- | --- | --- |
| `daily` | 内容形态 | `Log/DailyLogs/` 每日日记 | 启用 |
| `clippings` | 内容形态 | `Row/` 网页、视频、文章剪藏 | 启用 |
| `regulation` | 文档性质 | `Regulation/` 规范与说明类文档 | 启用 |

- 新增取值必须先登记到本表：写清分类维度与适用范围，再开始使用
- 目前只有"内容形态 / 文档性质"两类维度；要加主题维度（如 `obsidian`、`ai`）时，按「变更流程」逐条登记，不要一次铺开
- 表外的标签视为未登记，允许存在历史实例，但不得在新笔记中使用

## 使用规则

- 每篇 1–5 个；超过 5 个说明该改文件夹或加属性，而不是继续贴标签
- 写在 frontmatter 的 `tags` 下，一行一个值，**不带 `#`**
- 正文里引用标签才写 `#daily`；属性值里永远不写 `#`
- 不承载日期、作者、版本、评分、状态、天气这类可控值

## 与属性的分工

| 要表达的东西 | 放哪 | 例子 |
| --- | --- | --- |
| 文件处于什么状态（类别、时间、进度、评分） | 属性 | `type` `created` `focus_hours` |
| 内容讲的是什么（主题、领域、场景） | 标签 | `daily` `regulation` |
| 唯一归属（项目、领域） | 文件夹 | `Log/`、`Wiki/` |

判定口诀：**能枚举、需要排序统计的走属性；开放增长的主题词走标签。**

## 变更流程

1. 先查「词表」与现有笔记，确认没有同义词
2. 在本文件「词表」中登记：标签名、分类维度、适用范围、状态
3. 更新对应模板（如每日日记模板里的 `daily`）
4. 只改新笔记；批量回填旧笔记须单独提出并确认
5. 需同步 `.obsidian/types.json` 时，`tags` 字段类型已固定，通常无需改动

## 提交前自检

- [ ] 标签全小写、多词用下划线，不带 `#`、一行一个
- [ ] 1–5 个，且都在「词表」内
- [ ] 没有用标签表达日期、评分、作者、天气这类状态值
- [ ] 没有与 `type` 取值重复表达同一件事
- [ ] 新建标签已登记到「词表」
